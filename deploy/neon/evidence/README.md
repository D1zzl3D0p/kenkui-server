# Private evidence is stored outside Git

This directory contains instructions only. Never place actual exports, manifests, profiles, customer/credit rows, object-key inventories, dumps, age identities, provider settings, environment files, credentials, sessions or SMTP evidence in this checkout, even if ignored. Use the release operator's separately approved encrypted private evidence location with restricted directories/files and explicit retention/custody. `inventory.mjs` requires a positively classified owner-only private directory outside checkout and Git metadata, refuses unavailable/uncertain Git or dubious ownership, and writes new manifests exclusively with mode0600. A missing Git executable never permits writing. Ancestor `.git` entries are checked independently before Git discovery; inaccessible or unclassifiable metadata blocks output even if Git reports “not a repository.” Keep plaintext decrypt/restore material only in the approved offline isolated workspace; encrypt complete backups before shared R2 upload. No private age identity on services or in logs.

Retain a private chain for each environment/run: exact source authority/client and complete pagination; independent invitation policy plus Task13 staging database-writer/provisional attestations, separately from Task14 shared-source admission/final write-freeze attestations; source capture/export bytes and SHA256; approved fixture artifact/provenance/digest; per-owner full reviewed inventory, classification fingerprints and exact canonical strict-v1/v2 finance evidence; source-before/source-after/restored-copy manifests; original-column post-DDL projection and complete target review/digest; exact migration IDs; R2 listing provenance/keys/content checks; full backup/encrypted archive digest, owner recipient verification/custody and independent decrypt/restore; managed-auth data/config restore; actual runtime/backup role/RLS/negative-grant evidence; directory dry-run and atomic activation results; deployed revisions/overlays/route/readbacks; owner-requested login/mail/visible-book/credit acceptance; overnight control-plane usage and billing readback.

Keep these meanings distinct:

| Evidence | Meaning |
| --- | --- |
| Source export SHA256 | Exact authenticated export bytes; does not approve fixture classification |
| Fixture fingerprint | Existing reviewed selective ownership/entitlement classification; unchanged v1 encoding, even in manifest v2 |
| `restoredSnapshotDigest` | Direct existing locked `kenkui-restored-target-v1` application-inventory digest consumed by importer; NULL before all required tables exist |
| Restore `fullDigest` | Comparable complete table/schema/trigger/function/collation/sequence/invariant/R2 content plus original-column projection; not an importer/quarantine manifest |
| Restore `captureDigest` | Separately binds all environment/target/time/mode/auth-scope/projection provenance to content; integrity does not prove approval authorship |
| `restore-review-v1` | Mandatory independent operator attestation of exact original-source and expected destination pins/capture hashes/canonical provider database identities, purpose, approval provenance, migration/new-sequence delta and any exact historical pre-0004 evidence; no default/self-review |
| Archive SHA256 | Exact encrypted backup bytes; requires actual decrypt/restore proof |
| Native policy recovery bundle | Independently source-native ACL-inclusive archive/DEFAULT ACL TOC and projected SQL, encrypted artifact hash, exact source epoch/identity, actor/schema/kind coverage, original data archive hash, tooling/flags, reviewer and applied entries; `--no-acl` data/schema restoration alone proves no policy recovery |
| Default-ACL inventory | Exact future-object owner/scope/kind/grantor/tagged grantee/privilege/grant option, including empty ACLs, in existing `schemaObjects` and v2 hashes; separate from existing-object ownership/grants, memberships, RLS and effective access |
| Staging provisional evidence | Task13 staging DB-writer pause/transfer and expiring source/invitation evidence; shared WorkOS and production admissions remain live and unchanged |
| Final freeze attestation | Separately authorized Task14 shared-source admission freeze and relevant writer pause, independently verified final watermark/source/target freshness; a staging pause, hash or filename alone confers no final authority |

The tools expose only counts/status/digests on stdout and fixed sanitized failures on stderr. Private manifests still include sensitive account diagnostics and R2 references, so never paste them into chat or a PR. Record a nonsensitive evidence reference in acceptance/report documents, not private paths containing identifying labels or evidence contents. Preserve inactive and active directory/quarantine history under the existing no-automatic-pruning policy. Failed permission checks, unreadable tables, changed fingerprints, unknown provenance and unverified provider writes are blockers to record, never reasons to omit evidence or regenerate approvals.

For private restoration, keep the original no-ACL archive and its successful SQL/data recovery receipt, explicitly scoped to that result. Require the independently captured native policy bundle from the **same** frozen source epoch; a later export cannot certify an older archive by matching counts. Independently enumerate exact actors/schema/kinds, inspect DEFAULT ACL TOC entries and projected native SQL, and preserve completeness/provenance/review and both encrypted artifact hashes. Restore into a separately approved empty isolated database with audited exact-name inert NOLOGIN placeholders where needed, no capabilities/memberships/passwords, and no PUBLIC role creation. Stop on unsafe collisions or provider replay limitations. Restore complete original data, then the separately audited native DEFAULT ACL subset once with ACLs enabled and original owner/grantor semantics. Never derive policy SQL from expected manifest rows, rewrite principals or weaken strict copy review. Test global built-in-default revocation, empty definitions and grants. Retain fresh reviewed source/copy captures at the pinned collector revision.

Keep ownership, role definitions/memberships/inheritance, existing grants/RLS/routine access and provider Auth/service recovery alongside the bundle; inert placeholders alone prove none of those capabilities. Do not export password hashes or cluster globals. Prove owner-independent retained-artifact recovery and positive/negative effective access, including new objects under actual relevant creators. A durable bundle reused across backups needs positive source-policy stability evidence and explicit drift invalidation. The existing daily schedule still omits ACL/owner metadata; these docs do not implement a scheduled policy export. Occupied-target and DDL policy differences require separate private review bound to the same capture digests and DDL revision; never automatically replay source grants on live Neon. All live acceptance remains unchecked.
